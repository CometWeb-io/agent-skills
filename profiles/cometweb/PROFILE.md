# CometWeb publication and audit profile

This is a project overlay, not another editing skill and not an installation receipt.
Load it for CometWeb ebooks, PDF reports, audit workbooks and product audit readouts.
Do not automatically apply it to unrelated client brands or generic `ai-humanize` work.

## One entry point and precedence

Current explicit user instructions take precedence. For the series, use
`docs/COMETWEB-EBOOK-DESIGN-RULES.md` as the canonical reference.
`docs/EDITORIAL_VISUAL_STANDARD.md` remains supplementary guidance and historical
context, not a competing entry point. If they disagree on a material detail, record
and resolve the conflict; do not silently combine incompatible instructions.
When moving this overlay outside the repository, include both references; a path in
this file does not make a reference available to the receiving session.

## Non-negotiable output checks

Use the authentic approved CometWeb logo; never manufacture a replacement and call
it authentic. Use the Nunito Sans family by name. Do not distribute font binaries.
Keep the edition requested by the user; design refinement alone does not change 1.0.
Use red for confirmed before/defect states, green only for verified outcomes after a
repeat test, and a neutral treatment for missing or unassessed evidence. Status pills
combine text, an icon and a semantic rounded background; color alone is insufficient.
Prefer readable compact charts, a coherent icon set and a clear cover hierarchy.
Charts must distinguish measured data from illustrations; no invented statistics.
Render and inspect the final publication before claiming its visual QA passed. A
successful export is not a rendered visual review or accessibility certification.

## Audit coverage and repeat reviews

For exhaustive source or product audits, produce a coverage ledger before a full-
coverage claim: scope inventory, pinned source revision, inspected files/connections,
actual executions, evidence references and explicit gaps. Use
`tooling/validate_coverage.py` for structural consistency. Its successful result does
not authenticate the evidence or prove that a test was executed.
Never promote a code read, screenshot, success toast or previous-build test into proof
of present runtime behavior. A missing previous snapshot means delta unavailable.
