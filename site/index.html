    Routing

    One request, one owner

    tooling/route_skill.py scores a request against the routing signals in the registry. It is deterministic and runs offline, so routing can be tested before any model sees the prompt. It answers single_skill, workflow, ambiguous or no_skill; these are its real answers.

    CW-AIP v2

    Hand-offs are data, not prose

    When one skill feeds another, the result is a typed JSON envelope: twelve required core fields, a payload with its own schema and a SHA-256 of that payload. Pick a field to find it in a real fixture.

    Get started
    
              
    Preview first, then link what you need
    
            
    
            
    
              Installers symlink packages from your clone into each host's skills folder. They stop
              before changing anything when a path is taken, and --dry-run writes nothing.
            
    
          
    
          
    
            
    
              
    
                
              
    
              
    STEP 1
    
              
    Clone and preview
    
              
    Every check runs and the plan is printed. Nothing is written.
    
              
    $ git clone https://github.com/CometWeb-io/agent-skills.git
$ cd agent-skills
$ ./scripts/install-all.sh --dry-run
    
            
    
            
    
              
    
                
              
    
              
    STEP 2
    
              
    Install one skill
    
              
    Pick the host and the packages. Omit --skill to link all 33.
    
              
    $ ./scripts/install-claude.sh \
    --skill web-app-auditor
# or install-cursor.sh, install-codex.sh
    
            
    
            
    
              
    
                
              
    
              
    STEP 3
    
              
    Or use the plugin
    
              
    Claude Code can install the same skills from the marketplace, without a clone.
    
              
    $ claude plugin marketplace add \
    CometWeb-io/agent-skills
$ claude plugin install \
    cometweb-agent-skills@cometweb-agent-skills

    Built to be checked
    
              
    Read it, run the gates, verify the bytes
    
            
    
            
    
              The checks that guard main are one script you can run locally. Passing them shows a
              package keeps its contract; it does not show a model answers well.
            
    
          
    
          
    
            
    
              
    
                
              
    
              
    9,345tests
    
              
    Contract tests for every package
    
              
    
                Package scripts, validators, routing and installers are covered by pytest. The count
                is what pytest --collect-only reported on 7 Nov 2026.
              
    
            
    
            
    
              
    
                
              
    
              
    35gates
    
              
    Same list locally and in CI
    
              
    
                tooling/check_all.py holds every gate, from lint and SAST to routing
                evals and the leak scan. The Validate workflow runs exactly that script.
              
    
            
    
            
    
              
    
                
              
    
              
    SHApinned actions
    
              
    Locked-down workflows
    
              
    
                Every action is pinned to a commit, the default token is read-only and checkout does
                not keep credentials. A test fails if a workflow breaks one of these rules.
              
    
            
    
            
    
              
    
                
              
    
              
    Tree+ history
    
              
    Leak scan before anything lands
    
              
    
                The public-safety gate scans the working tree and the full Git history for keys,
                tokens, private paths and private hosts.
              
    
            
    
            
    
              
    
                
              
    
              
    SBOM+ attestation
    
              
    Release packages you can verify
    
              
    
                Tag builds produce per-skill ZIPs, SHA256SUMS, a CycloneDX SBOM and a
                GitHub attestation, kept as a draft until the owner publishes.
              
    
            
    
            
    
              
    
                
              
    
              
    5working days
    
              
    Private vulnerability reports
    
              
    
                Report through GitHub's private advisory form. The policy aims to acknowledge within
                five working days and lists what is in scope.

    What it won't claim
    
              
    Honest about its limits
    
            
    
            
    
              The repository is strict about the difference between a package that passes its checks
              and a skill that makes a model better at a task.
            
    
          
    
          
    
            
    
              
    
                
    
                  
                
    
                01
              
    
              
    Experimental packages
    
              
    
                Every skill ships marked experimental. Live task success for the catalog as a whole
                is recorded as not assessed.
              
    
            
    
            
    
              
    
                
    
                  
                
    
                02
              
    
              
    No model, no permissions
    
              
    
                Skills supply instructions and output contracts. The model, browser, connectors and
                any right to act stay with your host and with you.
              
    
            
    
            
    
              
    
                
    
                  
                
    
                03
              
    
              
    Valid is not correct
    
              
    
                A validator checks that an output keeps its contract. It cannot tell you the
                finding, verdict or claim inside it is right.
              
    
            
    
            
    
              
    
                
    
                  
                
    
                04
              
    
              
    Links follow your clone
    
              
    
                Installed skills are symlinks, so git pull changes them and deleting
                the clone breaks them. Use a pinned snapshot for stable work.
