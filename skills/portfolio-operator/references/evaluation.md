# Evaluation

A good Portfolio Operator run changes allocation only for evidence-backed reasons.

## Golden behaviors

1. **Client vs optional feature** — a near hard client commitment outranks an optional product improvement.
2. **Capacity honesty** — unknown capacity never turns into invented weekly hours or percentages.
3. **Overload** — incompatible large hard commitments surface as `CAPACITY CONFLICTS` rather than both appearing as effortless NOW work.
4. **Product boundary** — deep product sequencing delegates to Product Operator.
5. **Future gate** — work needed for a later motion stays WAITING/NEXT until it gates the active horizon.
6. **Explicit pause** — non-focus projects can be PAUSED/maintenance; the output does not give token work to every project.
7. **External promise protection** — a scoring function cannot silently drop a client/institutional commitment.
8. **Concise output** — detailed evidence stays in the sidecar.
9. **Specialist depth ceiling** — product/client/research internals do not leak into the portfolio brief; `portfolio_outcome` is rendered instead of deeper internal action text.
10. **Precision provenance** — exact dates/numeric targets never appear without `evidence_ref` or `user_defined=true`.
11. **Delegation reality** — hypothetical agents/owners are `DELEGATE CANDIDATE` or paused, not treated as real capacity.
12. **Cross-project hard-load conflict** — unknown capacity plus three substantial hard streams is surfaced explicitly.

## Regression smells

- every project appears in NOW;
- exact hours appear without a source;
- task count is mistaken for priority;
- repository activity dominates client/research commitments;
- a Product Operator or Release Readiness workflow is duplicated inline;
- a future gate is called a blocker merely because it is important;
- the assistant invents deadlines to produce a tidy calendar;
- a material strategic trade-off is hidden inside a numeric score;
- `MUST DO` becomes a component-level implementation checklist for one product/client;
- exact dates or KPI counts are invented to make the plan look operational;
- an unconfirmed agent/person is treated as real delegated capacity.
