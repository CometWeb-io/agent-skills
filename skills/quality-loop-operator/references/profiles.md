# Quality loop profiles

## EDITORIAL / SALES / TECHNICAL_DOCS
Required sequence in STANDARD/DEEP:

1. brief-architect
2. content-writer (or an explicitly external producer, recorded as such)
3. content-reviewer
4. content-roaster
5. repair-operator when material findings exist
6. artifact-acceptance
7. feedback-integrator only when observations should enter the learning loop

LIGHT may omit the roast when the user explicitly requests a lightweight reversible pass. DEEP may not omit reviewer, adversarial pressure test, repair of accepted material defects, or acceptance.

## RESEARCH

1. brief-architect / research contract
2. manuscript or analysis producer
3. constructive content review when communication quality matters
4. science-roaster
5. repair-operator / reanalysis
6. artifact-acceptance for the manuscript/deliverable

This does not replace `research-program-operator`, ethics/governance approval, or journal/conference acceptance.

## REPO_DEEP

1. repo-roaster
2. repair-operator when mutation is authorized
3. re-audit affected journeys/surfaces
4. hand off a specific candidate to `release-readiness` for GO/NO-GO/DEFER

`artifact-acceptance` may gate the audit report itself but never substitutes for software release readiness.

## SKILL_QUALITY

Use `skill-auditor` for static/package quality, then `skill-evaluator` for behavioral lift. Requested edits route to `skill-creator`; no empirical claim is allowed from static audit alone.
