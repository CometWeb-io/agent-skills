# Framework doctrine v4

Framework jest soczewką, nie dowodem.

Registry kernela:

- `strategic_choice`,
- `competitive_advantage`,
- `positioning_category`,
- `value_equation`,
- `customer_job_evidence`,
- `growth_loop`,
- `operating_constraint`,
- `reversibility_experiment`.

Ekspert może odrzucić przypisany framework. Evidence Judge może wykluczyć go z finalnego wsparcia.

## Doctrine packs

Książki i prywatne syntezy traktuj jak doctrine packs, nie persony autorów. Każda doctrina powinna mieć:

- applies_when,
- fails_when,
- assumptions,
- questions,
- evidence_needed,
- common_misuse,
- counter_doctrine.

Konflikt doctrine jest pożądany, jeśli ujawnia testowalne założenie. Nie wybieraj frameworku na podstawie autorytetu autora.

## Usefulness

Mierz, czy framework ujawnił ważne założenie/ryzyko, zmienił vote, wskazał test albo został sensownie odrzucony. Nie nazywaj tego "accuracy".
