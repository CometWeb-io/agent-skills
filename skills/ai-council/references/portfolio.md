# Portfolio and resource allocation v5

Decyzja może być dobra standalone, ale zła jako wykorzystanie ograniczonych zasobów.

Uruchom `portfolio`, gdy użytkownik porównuje projekty, inwestycje, kanały, hiring, roadmapę lub kilka równoległych decyzji.

Analizuj:

- wspólne zasoby i capacity,
- cash/capital exposure,
- dependency graph,
- sequencing constraints,
- opportunity cost,
- value density,
- conflicts między decyzjami,
- decyzje blokujące/umożliwiające inne decyzje.

Nie sumuj "atrakcyjności" bez sprawdzenia wspólnych ograniczeń. Gdy portfolio conflict istnieje, Chairman może rekomendować zmianę kolejności/alokacji mimo `GO` dla pojedynczych projektów.
