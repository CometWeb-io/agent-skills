## 3. Learning strategy

Choose one:

- `WEDGE_VALIDATION` — test whether one defined segment/workflow has repeated urgent pain and transferable solution fit.
- `SEGMENT_DISCOVERY` — intentionally vary segment/persona/company characteristics to learn where pull is strongest.
- `HORIZONTAL_TRANSFER` — keep workflow/persona relatively stable while testing transfer across industries or contexts.
- `ENTERPRISE_STRESS_TEST` — test security, procurement, integration, scale, or governance requirements with deliberately demanding organizations.

Do not vary every dimension simultaneously. State what remains constant and what is intentionally varied.

## 6. Mutual value

**Partner receives**: early capability, founder/product access, implementation help, influence within explicit boundaries, commercial consideration if applicable.

**Company receives**: workflow access, recurring usage/feedback, data or system access within agreed boundaries, implementation effort, candid failure reporting, reference only if separately agreed.

Never promise roadmap priority merely to win participation.

## 7. Capacity budget

Estimate before committing to cohort size:

- product/founder hours available per week,
- implementation/support hours per partner,
- research/interview hours per partner,
- maximum simultaneous high-touch partners,
- review cadence.

Use 5–10 partners only as a rough external reference, not a default law. High-touch technical programs may need fewer; horizontal discovery may justify more. Capacity and learning needs control the number.

## 8. Stop rules

Stop or redesign discovery when:

- new candidates add little new hypothesis coverage,
- repeated searches return the same weak evidence pattern,
- the target problem itself loses support,
- cohort capacity is already saturated,
- the expected information gain of another partner is lower than the implementation/support burden.
